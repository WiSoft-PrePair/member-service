# PrePair Client 요구사항 (Member · OAuth)

> 이 문서는 PrePair 백엔드 중 **회원 관리(Member)** 와 **OAuth** Bounded Context에 한정해
> 현재 구현된 백엔드 기능을 기반으로 역추적한 Client 요구사항이다.
> 각 요구사항은 실제 API 라우트 및 도메인 코드 위치와 매핑되어 추적성을 갖는다.
> ID 체계: `REQ-<도메인>-<번호>`

---

## 0. 서비스 개요 (본 범위)

PrePair 사용자는 회원으로 가입하고, 이메일·비밀번호 또는 카카오 OAuth로 인증을 거쳐 PrePair의 기능을 이용한다. 회원은 자신의 직업·닉네임·알림 채널·알림 빈도를 등록·수정할 수 있고, 비밀번호 변경·재설정·이메일 변경·탈퇴를 수행할 수 있다. 카카오 OAuth 사용자는 신규 가입, 기존 계정 자동 연결, 기존 계정 사후 연결의 세 가지 경로로 진입한다.

**기술 스택**: NestJS, Bun, MikroORM(Write), Prisma(Read), PostgreSQL, JWT, 카카오 OAuth, Nodemailer.

**모든 API의 공통 prefix**: `/api`

---

## 1. 회원 (Member)

### REQ-MEM-001 회원 가입
- **설명**: 사용자가 이메일·비밀번호·직업·닉네임·알림 채널·알림 빈도를 제공해 신규 회원으로 가입한다.
- **API**: `POST /api/members/register`
- **규칙**:
  - 이메일 형식 검증 통과 필수(`Email` VO)
  - 비밀번호 8자 이상(`Password` VO)
  - 이메일 중복 가입 불가(`EmailAlreadyExistsException`)
  - 가입 시 `point=0`, `isPro=false`로 초기화
  - `MemberRegistered` 도메인 이벤트 발행
- **매핑**: `MemberController.register` → `MemberRegisterCommand` → `Member.register()`

### REQ-MEM-002 이메일 인증 코드 발송 / 검증
- **설명**: 회원 가입·비밀번호 재설정·이메일 변경 전, 4자리 인증 코드를 이메일로 발송하고 사용자가 입력한 코드를 검증한다. 통과 시 5분 유효 등록 토큰(UUID) 발급.
- **API**:
  - `POST /api/members/email` — 인증 코드 발송
  - `POST /api/members/email-verify` — 인증 코드 검증
- **규칙**:
  - 코드는 5분간 유효, 만료 시 `InvalidVerificationCodeException`
  - 검증 통과 시 UUID 기반 `VerificationToken` 발급
- **매핑**: `SendEmailVerificationCommand`, `VerifyEmailCommand`

### REQ-MEM-003 회원 조회
- **설명**: 자신의 회원 정보를 조회하거나, 특정 회원 / 전체 회원 목록을 조회한다.
- **API**:
  - `GET /api/members` — 내 정보 조회(JWT 필요)
  - `GET /api/members/:id` — 특정 회원 조회
  - `GET /api/members/all` — 전체 회원 목록 조회
- **매핑**: `GetMemberQuery`, `GetMemberEmailQuery`

### REQ-MEM-004 회원 정보 수정
- **설명**: 직업, 닉네임, 알림 채널, 알림 빈도를 수정한다.
- **API**: `PATCH /api/members`
- **규칙**: 일부 필드만 변경 가능(선택 입력), `MemberUpdated` 이벤트 발행
- **매핑**: `MemberUpdateCommand` → `Member.update()`

### REQ-MEM-005 비밀번호 변경
- **설명**: 현재 비밀번호를 검증한 뒤 새 비밀번호로 교체한다.
- **API**: `PATCH /api/members/password`
- **규칙**:
  - 현재 비밀번호 불일치 시 `InvalidPasswordException`
  - 새 비밀번호도 정책(8자 이상) 검증
  - `MemberPasswordChanged` 이벤트 발행
- **매핑**: `MemberChangePasswordCommand` → `Member.changePassword()`

### REQ-MEM-006 비밀번호 재설정
- **설명**: 이메일 인증을 통과한 사용자가(등록 토큰 보유) 현재 비밀번호 없이 비밀번호를 재설정한다.
- **API**: `POST /api/members/password-reset`
- **규칙**:
  - 유효한 `VerificationToken` 필수(없거나 만료 시 `InvalidVerificationTokenException`)
  - `MemberPasswordReset` 이벤트 발행
- **매핑**: `ResetPasswordCommand` → `Member.resetPassword()`

### REQ-MEM-007 이메일 변경
- **설명**: 새 이메일에 대한 인증 코드 검증 후 회원의 이메일을 변경한다.
- **API**: `PATCH /api/members/email`
- **규칙**:
  - 새 이메일에 대한 등록 토큰 필수
  - 이메일 형식·중복 검증
  - `MemberEmailChanged` 이벤트 발행
- **매핑**: `ChangeEmailCommand` → `Member.changeEmail()`

### REQ-MEM-008 회원 탈퇴
- **설명**: 회원이 자신의 계정을 삭제한다.
- **API**: `DELETE /api/members`
- **규칙**: `MemberWithdrawn` 이벤트 발행
- **매핑**: `MemberWithdrawCommand`

### REQ-MEM-009 포인트 직접 적립
- **설명**: 외부 컨텍스트(또는 관리자)가 특정 회원에게 임의 포인트를 적립한다.
- **API**: `PATCH /api/members/:id/point`
- **규칙**: `Member.addPoint()` → `MemberPointAdded` 이벤트
- **호출자**: 본 도메인 외부 (예: 면접·리워드 컨텍스트, 관리자)

### REQ-MEM-010 리워드 적립 (외부 점수 기반)
- **설명**: 외부에서 산정된 점수를 받아 회원에게 포인트로 적립한다.
- **API**: `PATCH /api/members/reward`
- **규칙**:
  - 점수 → 포인트 환산 정책은 본 도메인 외부에 존재(현재는 컨트롤러 입력으로 주입)
  - `MemberPointAdded` 이벤트 발행
- **호출자**: 본 도메인 외부

> REQ-MEM-009 / REQ-MEM-010은 회원 도메인이 외부에 노출하는 인터페이스다. 점수 산정·환산 정책 자체는 본 리팩토링 범위 밖이며, 회원 도메인은 "포인트를 적립한다"는 행위만 책임진다.

## 2. 인증 (Authentication)

### REQ-AUTH-001 로그인
- **설명**: 이메일·비밀번호로 로그인하고 액세스 토큰·리프레시 토큰을 발급받는다.
- **API**: `POST /api/auth/login`
- **규칙**:
  - 비밀번호 불일치 시 `InvalidPasswordException`
  - `MemberLogin` 이벤트 발행
- **매핑**: `AuthService.login()`

### REQ-AUTH-002 토큰 갱신
- **설명**: 만료된 액세스 토큰을 리프레시 토큰으로 재발급한다.
- **API**: `POST /api/auth/refresh`
- **매핑**: `RefreshTokenService`

### REQ-AUTH-003 로그아웃
- **설명**: 리프레시 토큰을 폐기해 세션을 종료한다.
- **API**: `POST /api/auth/logout`

### REQ-AUTH-004 내 정보 조회 (인증 확인)
- **설명**: 액세스 토큰을 검증해 현재 로그인 회원 정보를 반환한다.
- **API**: `GET /api/auth/me`
- **규칙**: `JwtAuthGuard`를 통과해야 한다.

## 3. OAuth (카카오)

### REQ-OAUTH-001 카카오 로그인 URL 발급
- **설명**: 카카오 OAuth 인가 페이지로 리다이렉트할 URL을 발급한다.
- **API**: `GET /api/auth/kakao/url`
- **매핑**: `KakaoAuthService`

### REQ-OAUTH-002 카카오 콜백 처리 (3가지 시나리오)
- **설명**: 카카오 인가 코드를 교환해 사용자 프로필을 받고, 회원/연결 상태에 따라 분기한다.
- **API**: `POST /api/auth/kakao/callback`
- **시나리오**:
  1. **기존 회원 로그인** — 동일 카카오 연결이 이미 존재 → 액세스/리프레시 토큰 발급
  2. **자동 연결** — 카카오 이메일과 동일한 기존 회원이 있음 → `OAuthConnection.connect()`로 자동 연결 후 로그인
  3. **신규 등록 토큰 발급** — 기존 회원 없음 → 5분 유효 등록 토큰 반환(이후 가입 단계로 유도)

### REQ-OAUTH-003 카카오 신규 회원 가입 완료
- **설명**: 카카오 등록 토큰을 가진 사용자가 추가 정보(직업·닉네임·알림 설정)를 입력해 가입을 완료한다.
- **API**: `POST /api/auth/kakao/register`
- **매핑**: `OAuthMemberRegisterCommand`

### REQ-OAUTH-004 기존 계정에 카카오 연결
- **설명**: 이메일/비밀번호로 가입한 기존 회원이 자신의 계정에 카카오 OAuth를 사후 연결한다.
- **API**: `POST /api/auth/kakao/link`

## 4. 비기능 요구사항

### REQ-NFR-001 보안
- 비밀번호는 해시 알고리즘으로 저장(평문 저장 금지)
- 액세스 토큰(JWT) + 리프레시 토큰 분리
- `JwtAuthGuard`로 인증이 필요한 모든 엔드포인트 보호
- 도메인 예외는 컨트롤러 레이어 예외 필터에서 적절한 HTTP 상태 코드로 변환

### REQ-NFR-002 아키텍처
- 헥사고날 아키텍처 — 도메인 / 애플리케이션 / 어댑터 3계층 분리
- 도메인 모델 패턴(Domain Model Pattern) — Aggregate Root가 비즈니스 규칙을 보유
- Member Bounded Context는 CQRS + Event Sourcing
- OAuth, Auth는 Service 패턴(CQRS 미적용)
- 도메인 객체는 불변(`readonly` 필드 + 새 인스턴스 반환 패턴)

### REQ-NFR-003 영속성
- Write 모델: MikroORM
- Read 모델: Prisma (Member에 한해 분리 적용)
- Event Store: Prisma 기반 `PrismaEventStoreImpl`
- DB: PostgreSQL

### REQ-NFR-004 외부 연동
- 카카오 OAuth (인가 코드 교환, 사용자 프로필 조회)
- SMTP (Nodemailer — 인증 코드 발송)

### REQ-NFR-005 코드 품질
- 패키지 매니저: `pnpm` (`pnpm-lock.yaml` 기준)
- 린팅·포매팅: Biome
- `any` 타입 사용 금지

## 5. 본 리팩토링에서 다듬을 후보

도메인 모델의 후보 보강 항목과 1:1로 연동되는 요구사항 관점 항목.

- **REQ-REF-001 비밀번호 정책 명세 확정** — 8자 이상 외에 대소문자/숫자/특수문자 정책을 도메인에 포함할지 결정.
- **REQ-REF-002 인증 코드 자릿수 정책** — 현재 4자리. 6자리로 상향할지 결정 후 `VerificationCode.generate()` 갱신.
- **REQ-REF-003 등록 토큰 자료형 정합성** — UUID vs JWT 결정.
- **REQ-REF-004 회원 탈퇴 도메인 메서드 등록** — `Member.withdraw()`를 명시적으로 두고 `MemberWithdrawn` 이벤트 발행 일관화.
- **REQ-REF-005 `MemberRegistered` 이벤트 payload에서 비밀번호 해시 제거** — 이벤트 스토어에 해시가 흘러가는 것을 차단.
- **REQ-REF-006 OAuthProvider Enum화** — 타입 별칭 → Enum 또는 Branded Type 승격.
- **REQ-REF-007 `MemberPointAdded` 이벤트 파일 분리** — `events/` 디렉토리에 명시적 이벤트 타입 추가.
